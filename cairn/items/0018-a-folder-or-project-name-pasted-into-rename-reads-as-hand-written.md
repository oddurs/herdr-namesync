Clearing a name in herdr's rename dialog does not submit an empty string -- it
appears to put a directory name back. namesync then sees a label it did not
write, concludes a human chose it, and holds the workspace for good.

The label it holds is the one thing that is definitely not a considered name:

  unifont                        -> held    (the checkout folder)
  fontina                        -> held    (the project itself)
  feat-collection-relative-paths -> adoptable

Only the last matched, because `looksAutoGenerated` compared against the
basename of whichever directory detection happened to resolve -- here a
worktree that has since been deleted.

Anything that merely restates where the workspace lives, or what the project is
called, is not a description of work. Compare against all of them: the project
name, the pane's own directory, the foreground directory, and the branch.
